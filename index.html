최고 관리자 승인 절차

협업자는 원본의 본인 작업 브랜치 users/<본인 로그인>/<작업명>에 푸시한 후 develop 대상 PR을 엽니다. 직접 push와 웹 머지는 차단되지 않으며 PR 순서는 운영 규칙입니다. 최고 관리자가 검토한 HEAD SHA를 명시해 승인·머지합니다. Free 비공개 저장소의 필수 리뷰 보호 기능을 강제했다고 표시하지 않습니다.

node scripts/branch-governance.mjs check-pr <PR번호> --credential-manager
node scripts/branch-governance.mjs merge-pr <PR번호> --approve-sha <검토한_HEAD_SHA> --credential-manager

실제 코드·커밋·PR·로그 접근은 로그인한 로컬 Next.js 관리자의 브랜치·승격 관리 메뉴에서 가능합니다.

PC·서비스 준비 체크리스트

이 화면의 테스트는 가상 실행입니다. 실제 테스트 전에는 staging의 정상 health 응답, CPU·메모리 여유, 진행 중 배포·백업 여부를 확인합니다. 생성기만 실행할 때 논리 CPU 2개·RAM 4GiB를 준비 기준으로 검토하고, Docker Desktop은 공식 요구사항을 충족해야 합니다. Jenkins·앱까지 같은 PC라면 RAM 16GiB 이상을 권장 기준으로 검토하세요. 사양만으로 성능을 보장하지 않습니다.

처음에는 1 RPS·동시 1·3초로 확인하고 점진적으로 늘립니다. 오류·OOM·반복 재시작이나 CPU/메모리 포화가 발생하면 중단합니다.

무료 범위 확인

    
Jenkins와 Mailer 자체는 오픈소스로 사용할 수 있습니다. SMTP 발송료는 연결한 메일 서비스 요금제에 따릅니다.

    
개인 Gmail은 하루 500건 초과 발송 또는 한 통의 수신자가 500명을 넘는 경우 발송 제한이 발생할 수 있습니다. 계정의 전체 발송량에 적용됩니다.

    
GitHub 무료 제공량과 초과 차단 설정은 계정 Billing에서 확인하세요. 계산·저장 공간·이미지 보관은 각각 확인해야 합니다.

    
GitHub Billing · GitHub 공식 무료 제공량 · Gmail 공식 발송 제한
